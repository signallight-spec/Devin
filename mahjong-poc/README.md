# mahjong-poc — 手出し/ツモ切り検出PoC

眼鏡型デバイス用アプリの事前検証: 麻雀動画から「各捨牌が手出しかツモ切りか」を検出・記録し、可視化するパイプライン。

## 方式

1. **捨てイベント検出** (`pipeline3.py`)
   - 河(R_POND)に手がかぶさる区間 = 肌色画素のスパイク
   - 区間前後で河の牌面積が閾値以上増加 → 捨てと判定
2. **手出し/ツモ切り判定**
   - 捨ての前後で、手が写っていないクリーンフレームの手牌列を差分比較（±60pxアライメント、肌色画素は除外）
   - 列の内部から牌が消えた → 手出し
   - 列に変化なし → ツモ切り（ツモ牌が列に入らずそのまま河へ）
   - 列右端のみ変化 → ツモ牌を右端に置く流儀の可能性（`tsumogiri?`）
3. **可視化** (`annotate.py`)
   - 河の新規牌ブロブで捨て牌位置を推定し、持続マーカーを描画（赤T=手出し、青M=ツモ切り）
   - 配牌/局切り替えの長いエピソード中はマーカーを消去

## 結果（検証動画: YouTube「【三人麻雀 福岡 4K】手牌が見やすい麻雀動画」）

- 捨てイベント 21件 → 手出し 6 / ツモ切り 14 / 不明 1（局間の切れ目）
- `events3/` に各イベントの before/after 帯画像（判定根拠）

## 使い方

```bash
python3 pipeline3.py <video.mp4>   # log3.json, events.json, events3/*.png を生成
python3 annotate.py <video.mp4>    # annotated.mp4 を生成（log3.json と events.json が必要）
```

ROI座標（R_POND, R_HAND）は1280x720のこの動画専用。別動画では再設定が必要。

## 既知の限界

- 肩越し固定カメラ前提。眼鏡POVの手ブレ・移動視点は未検証
- 捨て牌マーカー位置は近似（新規牌ブロブ重心）
- 「ツモ牌を列右端に置いて切る」ケースは右端変化で区別がつかず `tsumogiri?` になる（要ツモ牌位置追跡）
- 副露列の上部が帯にかぶる場合、メルド変化を手出しと誤ることがある
